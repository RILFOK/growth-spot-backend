# Backend — заявки и антиспам

## Назначение
Backend обрабатывает заявки, отправленные с публичной формы сайта, и содержит встроенную антиспам-логику.

Основной endpoint для создания заявки:

`POST /api/leads`

## Общая логика обработки заявки
При получении заявки backend:
- нормализует входные данные;
- валидирует имя, телефон и сообщение;
- определяет IP-адрес отправителя;
- проверяет ограничения антиспама;
- сохраняет заявку в базу данных или отклоняет запрос.

## Валидация

### Имя
Проверяется, что имя:
- обязательно;
- содержит от 2 до 40 символов;
- состоит только из русских букв, пробелов и дефисов;
- не содержит цифр;
- не содержит мусорных значений;
- не содержит нецензурных выражений;
- не выглядит бессмысленным текстом;
- не входит в список типовых fake-имён.

### Телефон
Телефон:
- нормализуется к формату `+7XXXXXXXXXX`;
- должен соответствовать российскому номеру;
- отклоняется, если не может быть корректно приведён к допустимому формату.

### Сообщение
Сообщение:
- является необязательным;
- должно содержать минимум 5 символов, если заполнено;
- ограничено 1000 символами;
- не должно содержать profanity;
- не должно содержать мусорных данных;
- не должно содержать ссылок;
- не должно выглядеть бессмысленным текстом.

## Защита от спама
Для защиты от злоупотреблений backend использует несколько уровней проверки:
- duplicate check по активному номеру телефона;
- ограничение количества активных заявок на один IP;
- whitelist IP;
- blocked IP.

### Duplicate check
Если в системе уже есть активная заявка с тем же телефоном и статусом `new` или `in_progress`, новая заявка отклоняется.

### Ограничение по IP
Backend отслеживает количество активных заявок, созданных с одного IP-адреса.

Если IP не находится в whitelist, количество таких заявок ограничивается.

## Логика блокировки
Если IP не находится в whitelist и активных заявок с него становится 3 или больше:
- IP заносится в `blocked_ips`;
- новые заявки помечаются как `is_spam = true`;
- связанные новые заявки могут быть дополнительно помечены как спам;
- клиент получает ответ с кодом `429`.

## Поведение при блокировке
При срабатывании антиспам-логики backend может вернуть ответ, содержащий:
- признак `spam`;
- признак `blocked`;
- IP-адрес;
- сообщение о блокировке.

Это позволяет frontend корректно показать пользователю причину отказа в отправке формы.
