# Backend — архитектура

## Общая схема
Backend реализован как монолитный Express-сервер в одном файле `index.js`.

Приложение предоставляет REST API для frontend части проекта и работает за reverse proxy (nginx).

## Архитектурные особенности
- backend запускается локально на `127.0.0.1`;
- внешний доступ к API предполагается через nginx по пути `/api`;
- приложение использует PostgreSQL как основную базу данных;
- авторизация реализована через JWT;
- доступ к части endpoint'ов ограничивается ролями пользователей.

## Общий подход
Backend построен как единое приложение без разделения на отдельные контроллеры, сервисы, роуты и слои доступа к данным.

Вся бизнес-логика, маршруты API, проверки прав доступа, валидация данных и работа с базой сосредоточены в одном файле. Такой подход упрощает старт разработки, но при росте проекта может усложнять сопровождение, тестирование и масштабирование.

## Middleware

### Глобальные middleware
- `cors()`
- `express.json()`

### Route-level middleware
- `authenticateToken` — используется для защищённых endpoint'ов

## Особенности запуска
- host: `127.0.0.1`
- порт по умолчанию: `3001`
- включён `trust proxy`

Backend не публикуется напрямую наружу и рассчитан на работу за nginx, который:
- принимает внешние HTTP/HTTPS-запросы;
- проксирует API-запросы на backend;
- раздаёт frontend как статические файлы.

## База данных
Используется PostgreSQL через `pg.Pool`.

Подключение к базе выполняется через строку подключения из переменной окружения `DATABASE_URL`.

## Основные функциональные блоки
В текущей реализации backend включает следующие функциональные блоки:
- авторизация и 2FA;
- заявки;
- антиспам;
- blocked IP;
- whitelist IP;
- пользователи;
- настройки сайта.

## Особенности текущей реализации
Ключевые особенности архитектуры:
- API и бизнес-логика не разделены на модули;
- SQL-запросы формируются прямо в коде обработчиков;
- проверка прав доступа выполняется внутри endpoint'ов;
- часть логики безопасности завязана на взаимодействие frontend и backend;
- приложение ориентировано на один backend-процесс под управлением PM2.

## Возможные направления развития
При дальнейшем развитии проекта архитектуру можно улучшить за счёт:
- разделения маршрутов по модулям;
- выделения сервисного слоя;
- выделения слоя доступа к базе данных;
- добавления полноценной системы миграций;
- добавления автоматических тестов для ключевой бизнес-логики.
