# Backend — настройки

## Назначение
Backend предоставляет отдельный набор endpoint'ов для чтения и изменения настроек сайта.

Настройки используются как публичной частью frontend, так и административной панелью.

## Endpoint'ы
- `GET /api/settings/public`
- `GET /api/settings`
- `PUT /api/settings`

## Формат хранения
Таблица `settings` используется как key-value хранилище.

Каждая запись содержит:
- ключ настройки;
- значение;
- время последнего обновления.

## Публичные настройки
Endpoint `GET /api/settings/public` возвращает объект формата:

`{ "key": "value" }`

Этот endpoint не требует авторизации и используется frontend для загрузки публичных данных сайта, например:
- контактов;
- ссылок на мессенджеры;
- текстов hero-секции;
- аналитических идентификаторов.

## Приватные настройки
Endpoint `GET /api/settings` возвращает массив записей из таблицы `settings`.

Этот endpoint используется административной частью для получения полного списка настроек в форме, удобной для редактирования.

## Обновление
Endpoint `PUT /api/settings` выполняет upsert для каждой пары `key/value`.

Если ключ уже существует, его значение обновляется.
Если ключа нет, создаётся новая запись.

## Важная особенность
На backend нет отдельной проверки роли для изменения настроек — только проверка авторизации.

Это означает, что любой авторизованный пользователь технически может вызвать `GET /api/settings` и `PUT /api/settings`, если доступ не ограничен на уровне frontend.

## Рекомендация
Для повышения безопасности рекомендуется добавить серверную проверку ролей для endpoint'ов изменения и чтения административных настроек.
